# SNEHA UI/UX and accessibility audit

Scope: UI and UX only, for the Flutter patient app (`apps/patient_app`) and the React caregiver/clinician dashboard (`apps/web_dashboard`). This audit makes no backend, API, data-model or business-logic recommendations. Where a UI problem starts in backend behaviour, the fix suggested here is a presentation-level one.

Evidence base:

- Source as it stood on branch `stage-8-security-validation`, including uncommitted changes.
- Dashboard baseline screenshots in light mode with synthetic data (`baseline/<page>@1440x900.png`, `@390x844.png`) and `baseline/report.json`. The report measured 0 px horizontal overflow on every page. Analytics page height was **5,221 px at 1440 wide and 9,471 px at 390 wide**.
- Patient app screenshots (`baseline_app/NN_<screen>_{small_360x640,typical_412x915}.png`).

> **Harness limitation (not an app bug).** In the patient-app renders, text inside `FilledButton` and `OutlinedButton` appears as black or white boxes. Those button styles set no `fontFamily`, and the test font draws boxes. Button labels in this audit come from `lib/l10n/strings.dart`. `01_welcome_*` caught `RootGate`'s loading view rather than the welcome screen, so the welcome screen was audited from source only.

Severity scale:
- **critical**: blocks or seriously harms a core task, or makes content unreadable.
- **high**: frequent friction or a WCAG failure on a main path.
- **medium**: noticeable inconsistency or confusion.
- **low**: polish.

### 2.4 Accessibility (A11Y)
